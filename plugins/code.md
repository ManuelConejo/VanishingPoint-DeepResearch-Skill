# Plugin code - contributions of a project Y to a project X (2026-10-26)

Read by the engine (SKILL.md). Four fixed sections, then five sections specific to this plugin ("Framing before collection", "Composite synthesis", "Whole reading before verdicts", "Context capsule", "Modes"). Every source says where its facts were established (adapter code, documentation, probe date); "not established" = not established anywhere. Every key is optional. **Foreign code is read at a SHA, through the gateway or in an isolated container supplied by the host project**: VP never executes the code of Y, never clones it itself and never starts a container.

## Sources

Block read by `tools/gateway.py` (format README.md). Five code engines are wired by `tools/code_sources.py` and served **only** when a plugin declares them here: `code` (`search-code`: Sourcegraph, then GitHub if token), `versions` (registry plus deps.dev), `paper-code` (HF Papers), `provenance` (Software Heritage), `ecosyste.ms` (command `usage`: package usage). The other names stay `not_wired` and are refused cleanly. If `sources` returns no wired engine, the run stops there: empty `result.json`, reason in `saturation`, nothing is claimed. Access marked according to `ACCESS-POLICY.md` (`api` level 1; `page` level 2, pacing 1 request / 2 s / host, declarative UA, cache, stop on 429/403; `browser` reserved and unused (no browser route); `tos_forbidden`, `technical_block` level 3, listed and disabled). Probes dated 2026-10-26 unless stated.

Common transport (`tools/code_sources.py`, `CodeClient`): HTTPS only, port 443, declared hosts, **no redirection** (a token must never follow a redirect), 2 s between calls per host except GitHub (6.1 s), 5 MB per response, receipts in `state/requests.jsonl` with the SHA-256 of the bytes and no credential; HTTP errors, 429 and malformed JSON stay typed errors, never an empty result. No anti-bot circumvention (ACCESS-POLICY.md). An unknown quota is not a permission to hoover.

Releases and commits endpoints: **not probed** (not established: do not call them until wired in the gateway; record `not established`).
   - Query: identifier or literal pattern, never a natural question; `limit <= 100`.
   - Date bound: **server filter established** for repositories: qualifiers `created:>YYYY-MM-DD`, `created:<day before T`, `pushed:` in `search/repositories`; `pushed_at`, commit and release dates serve the local re-check.

Without token: `{"status":"skipped","reason":"credential_missing"}` for `search/code` and GraphQL (token required, GraphQL 403 anonymous).

## Discipline biases

Shared catalogue: `vp-bias-catalogue/1`, discipline file `code` (`usage = "signal"`, 8 defects `code.*`, 13 references). Code **is not measured** against the catalogue set; its central defects (known vulnerability, non-existent package, licence, version) belong to the **mechanical verifier** on a primary base (OSV/GHSA), not to the LLM judge; if that base or tool is not wired in the run, the field stays UNVERIFIED, the LLM judge does not validate it instead. Ids: `code.deprecated_api`, `code.version_mismatch`, `code.known_vulnerability`, `code.licence`, `code.abandoned`, `code.outdated_dependency`, `code.hallucinated_package`, `code.unpinned`. The biases specific to the task "contribution of Y to X" have no catalogue id; they are listed below with their measurement.
- **Names do not say what the code does.** Masking capability names degrades LLM precision and recall (p < 0.001): they rely on lexical cues (Nguyen et al. 2026). Traceability false positives = assumptions drawn from names, phantom links (Alor et al.). Consequence: judge a mechanism on its body and its tests, never on its identifier or the README.
- **Adopted != useful; removed != bad.** Measured on our benches: 0 of 54 contributions has a before/after figure; "adopted" = file and symbol present at HEAD, not a verified behaviour. The 23 "removed" ones were deleted by 3 clean-up commits of the host project as dead code ("dropped in, never wired"), not judged bad; they are not valid decoys.
- **Licence before the code** (`code.licence`). Read the licence (API `license.spdx_id`, LICENSE file if NOASSERTION) before opening a file; "MIT" in the README without a LICENSE file (seen in a real use case), non-commercial licence hidden behind NOASSERTION (RepoAudit), repositories without licence (CrossSim, LEGION, GitTaskBench, but4reuse). Copy or clean-room is decided there, not afterwards.
- **Pin everything to a SHA** (`code.unpinned`, `code.version_mismatch`). Measured on our benches: 21 of the 36 links of an answer key pointed to a branch, not a commit (58 %), refused by the static verifier. A `search/code` hash is a blob, not a revision; grep.app's `branch` is not a SHA.
- **An LLM judges the equivalence of two codes poorly.** "Minimal" gap between LLM and lexical matching (SeqCoBench); an embedding classifier beats every LLM across languages by about 1 to about 20 points (Moumoula et al.). Hence **cite, do not assert**: a snippet on both sides at a frozen version, and a before/after test for the host project.
- **Mechanism never reused elsewhere.** Be wary without excluding it: look for at least one second use (Sourcegraph, ecosyste.ms dependents); if there is none, say so in the card (`reuse elsewhere: 0 found`), which is neither a proof nor a rejection.
- **Temporal leakage.** Live indexes (grep.app, Sourcegraph) and model memory; needs reconstructed after the fact (measured on our benches: 3 dates too late in one pilot). Freeze X and Y before the study, date the request.
- **"The right call" != "it works"**: correct changes 89-94 % but tests passed 36-64 % (PyMigBench); ideas well rated on paper degrade at execution (Si et al.); more than half of reuse failures come from the environment and the dependencies (GitTaskBench).
- **Dependencies** (`code.known_vulnerability`, `code.outdated_dependency`, `code.deprecated_api`, `code.abandoned`, `code.hallucinated_package`): deps.dev `advisoryKeys` read; a package absent from the registry is a hallucinated package (404 "Package not found"); an inactive repository (e.g. RepoAgent since 2024-12) is context to write down, not a verdict.
- **Popularity and preference**: stars and likes are context, never a proof; an LLM judge's preference does not predict real borrowing (measured on our benches: 2/26 in both arms).
- **What converted for the owner**: a mature tool from a neighbouring domain, read at a SHA, aimed at an existing seam; "URL + interesting?" without a dated need ends in 1 WATCH then nothing (measured on our benches).

## Output format

Format drawn from the real use of the reference deep-research skill ("what code vs code means", "what a code module should do"): **one finding per mechanism**, never one note per repository.

**Report (`REPORT.md`, SKILL.md section 5)**: argued prose in the eight sections of the output contract. The `Introduction` gives X@SHA, Y@SHA (or the list of Y), licence of Y (SPDX, source of the reading), request date and T, mode (Y given / need only), context capsule used (path, SHA). In `Main Analysis`, each finding (`### Finding n — <mechanism> (<GO | WATCH | NO-GO>)`) is argued in four steps: **Y side** (what the mechanism does, cited snippet, tests that cover it, reuse elsewhere found, each location cited by its `[n]` from the bibliography); **X side** (target seam existing or absent, equivalent present / partial / not found / absence established / undetermined, contributions registry, `[n]`); **consequence** (what X would gain, guarantees not transferred, dependencies, licence: copy allowed / clean-room / forbidden); **verdict** GO / WATCH / NO-GO with the criterion that prevails, the proposed before/after test in natural language (false-green mutant or counter-fixture, expected measure; VP does not write its code), and for WATCH the dated wake-up condition. Locations `file:line@SHA` are **never written inline**: every file read (Y side and X side) is an entry `[n]` of `Bibliography` with its permalink `blob/<sha>/...#L`, and the text cites `[n]`. `Limitations & Caveats` contains "what not to borrow"; `Methodology Appendix` contains the receipt of the sources (calls, quotas, 429, `skipped`), the list of Y read and their licences, and the scaffolding filed apart from the product core.

**Machine annex (SKILL.md section 6, produced by the last short call from the report)**: `mechanisms.json`, one object per finding with exactly these ten fields, in order: 1 `mechanism` (short name, one sentence on what it does); 2 `y_side` (`file:line@SHA`, cited snippet, tests, reuse elsewhere: 0, 1, n; where); 3 `x_seam` (`file:line@SHA` on the X side, existing or absent); 4 `already_in_x` (`present / partial / not found / absence established / undetermined`); 5 `verdict` (`GO` / `WATCH` / `NO-GO`, criterion that prevails); 6 `do_not_borrow`; 7 `licence` (copy allowed / clean-room mandatory / forbidden; licence of Y and compatibility with that of X); 8 `before_after_test` (natural language); 9 `wake_up` (dated condition, WATCH); 10 `verified_status` (each `file:line@SHA` checked byte for byte at the SHA; each figure with its level-1 verdict; a SOURCE-UNAVAILABLE or UNVERIFIED field stays flagged as is, never converted to a verified fact, SKILL.md section 7; it changes the verdict only through rules 2 and 3 below). `card.json` carries the atomic claims of the findings (one per fact, one source `[n]`). `result.json` (SKILL.md section 6) admits only `pmid:` / `doi:` / `arxiv:` identifiers (`tools/validate_result.py`): only documents that have one (papers linked by HF Papers, arXiv) enter it, with the six `criteria` ("not applicable" if need be); mechanisms and repositories stay in `REPORT.md` and `mechanisms.json` (a `repo:` identifier is not supported yet).

## Verification rules

Level 1 (`tools/verifier/ROLE.md`, the level-1 verifier role; `tools/verifier/citation_check.py`), plus:
1. **Code reference**: every `file:line@SHA` is verified by reading the file at the SHA (GitHub API `blob` or engine `provenance`, always through the gateway), snippet compared byte for byte; symbol and signature confirmed by the mechanical tool when supplied (tree-sitter; measured on our benches: 100 % of mutations never "verified", false alarms 0.5 % on a fresh sample); without that tool, the snippet is verified by reading and symbol/signature stay UNVERIFIED. A reference to a branch is **refused** (`unpinned`), not converted.
2. **Licence**: the licence of the card is re-read on the API (`spdx_id`) and, if `NOASSERTION` or absent, in the LICENSE file at the SHA; a card without a read licence is `SOURCE-UNAVAILABLE` for the licence field, and the verdict cannot be GO.
3. **Host seam**: `file:line@SHA` on the X side exists at the SHA of the capsule; otherwise `seam missing`, verdict at most WATCH.
4. **Equivalence**: every sentence "does the same as" or "replaces" requires two cited snippets and a proposed test; without them, `DISTORTED` (claim stronger than its proof).
5. **Dates**: SHA of Y earlier than T of the request; package version published before T (deps.dev `publishedAt`); otherwise the element is excluded and listed.
6. **Packages**: exact version, date, `advisoryKeys` read; "no dependency" is admissible only if `requires_dist` is present and empty.
7. **Reuse elsewhere**: the mention "reused by N projects" cites the repositories (Sourcegraph, ecosyste.ms); without a receipt, `ABSENT`.
8. **Token**: no token appears in the card, the receipt or the URLs; a receipt that contained one invalidates the report.
9. **Sandbox**: the report declares the reading mode: isolated container (image, SHA of the cloned Y) when the host project supplies one, otherwise `read through the gateway at the SHA, no clone`; in both cases no execution; a report that mentions an execution of the code of Y is refused.
10. **Mechanical retraction check (rule shared by all plugins)**: for every retained DOI (papers linked by HF Papers or arXiv with DOI), the verifier reads Crossref `/works/<DOI>`: `has-update` then `update-to` (`update-type`: `retraction`, `erratum`, `expression_of_concern`), and cross-checks with Retraction Watch (CSV `crossref/retraction-watch-data`); **no model call** (measured on our benches: 30/30 detected). `unknown` stays `unknown`. Code-side counterpart: OSV advisories read mechanically (source 10, `vulns`; GHSA source 11 not wired), otherwise `code.known_vulnerability` stays UNVERIFIED. Done by `tools/finish_run.py` (SKILL.md section 8; `retractions.json`), no gateway call.

## Framing before collection (scope.md, mandatory, written BEFORE any reading of Y)

What separates the STRONG studies from the NOISE studies in real use (measured on our benches): the framing written before collection, with a borrowing criterion and a verdict scale, and the host code recorded as a source. The engine (SKILL.md section 2) writes `scope.md`; for this plugin it contains, in this order, and no reading of Y starts before:
1. **X@SHA and Y@SHA** (or the list of candidate Y, each at a SHA; "need only": X@SHA and the need by goal), taken from the capsule.
2. **Borrowing criterion**, in one verifiable sentence: "closes a demonstrated gap in X" (which one, `file:line@SHA`), "gives a more biting test" (which measure), or **"gives X a capability it does not have"** (which one: a question X cannot answer today and could afterwards; the closest seam cited `file:line@SHA`, and "not found" searched as in point 4). A mechanism that satisfies none of the three is not a card, even if elegant; it stays **inventoried** in `searches/` (a piece worthless alone can count in an assembly). The question put to Y is phrased **as a capability** ("what could X do that it cannot do, if these pieces were assembled?"), never only as a local gap ("where does X lack this file?"): a local gap is seen piece by piece, a capability is seen only by reading Y as a system.
3. **Expected verdict scale**: what would make GO, WATCH, NO-GO for this request, written before looking at Y (existing seam, licence, installation cost, dependencies, proven equivalence).
4. **Host code declared as a source**: every target seam and every possible equivalent on the X side enters the sources table of the card under a key `local:<path>@<SHA>`, like a repository that was read; "already covered" is searched **in the registry and in the host code**, and cited (`present / partial / not found`), never deduced from a name. The host code X, frozen at the SHA of the capsule, is an **input of the request**, read in place, read-only: it is not a documentary access in the sense of SKILL.md section 0; for everything that is not X, the gateway remains the only access.
5. **Counter-example** ("what not to borrow", "what would make it red"): before reading Y, per target seam (or per mechanism already named in the capsule), the concrete situation on the X side where a borrowing would be a mistake (guarantee not transferred, dependency, environment of Y, invariant of the core); after reading, it is completed per mechanism in field 6 of the card and is the basis of the before/after test (field 8).
6. **Map of Y as a system, to be filled by the searchers**: `scope.md` reserves, before reading, a "Map of Y" block of three empty lines - *who feeds what* (which file produces which data, who reads it, through which key), *invariants that Y enforces* (what a tool of Y refuses: e.g. "a study must exist in the bibliography before entering the matrix", with `file:line@SHA` and the wording of the refusal), *what Y can answer thanks to that* (a question its linked data allows). The instructions of every searcher ask to note next to each mechanism, even trivial alone, **its flows** (who produces, who reads, through which shared key, with references or "not found") and **every invariant read**, not only the isolated capability; the engine fills the map in section 4 from the `searches/` files, without a new reading; a line that the searches do not allow to fill is written "insufficient evidence", never deduced, and any capability that depends on it caps at WATCH.
A study whose `scope.md` is missing or was written after the first readings is labelled `scope missing` and its verdict cannot be GO.

## Composite synthesis (after SKILL.md section 4, before the verdicts of section 5)

What the piece-by-piece verdict does not see (a real use case, 2026-10-27): three mechanisms each WATCH or NO-GO (canonical bibliography, key reused as a reference, derived columns) together formed a capability absent from X - evidence linked across reports, queryable ("what falls if this source is retracted?"). Before writing `Main Analysis`, the engine writes in `scope.md`, under "Composite synthesis":
1. The **map of Y** (point 6 of the framing), filled from the `searches/` files: each line cites its `file:line@SHA`, no invariant is deduced from a name.
2. The **capability question**: "if these pieces were assembled, what could X do that it cannot do?" - the engine examines **every group of mechanisms linked** by a shared key, flow or invariant (groups recorded, with the rejection reason for those that yield nothing), then answers in one sentence per candidate capability, with the pieces (mechanisms already cited), the closest X seam (`file:line@SHA`, or "not found" searched: then the capability caps at WATCH), what remains with X (the verifier, the identity of the sources) and what would be new.
3. For each candidate capability, a **"composite capability" finding** in `Main Analysis`, argued like the others (Y side, X side, consequence, verdict): the pieces keep their citations and their verification status; the licence of the assembly is **the most restrictive of the pieces** (copy / clean-room / forbidden); **the assembly is marked as an inference** ("this suggests") and its before/after test bears on the capability (a question X could not answer before and can afterwards), not on a piece. The verdict bears on the capability: it can be GO or WATCH while each piece alone is NO-GO ("already present" or "gap not demonstrated" do not block the assembly); it cannot be GO without a cited X seam, without a capability test, or if a piece is blocking (licence "forbidden" or SOURCE-UNAVAILABLE, core invariant, refusal of the capsule).
4. `Synthesis & Insights` **must** contain a "Composite capability" paragraph: either the retained capability or capabilities in one sentence each (with their `[n]`), or "none, because ..." with the groups examined (the pieces are linked by no shared key; the capability already exists in X, cited; the licence forbids it; the invariants of Y hold only through its interface) - "none" without this trace is a missing finding. The verifier (section 7) checks the pieces, the seams, and for the assembly: that every link is marked inferred, that the test bears on the capability and that the verdict respects these bounds; creativity adds to rigour, it takes nothing from it.

## Whole reading before verdicts

What the parallel searches do not see: the composite capability comes from reading Y and then X **in one block** by **one reader**, not from a prompt nor from a model family. After the searches (SKILL.md section 3) and the triangulation (4.1-4.3), **before** the plan revision (4.4), the composite synthesis and any verdict, the engine runs **once**:
`python3 -I tools/whole_reading.py <run dir> --y-repo <bare repo> --y-sha <sha> --x-repo <repo> --x-sha <sha> [--x2-repo <repo> --x2-sha <sha>] [--model M] [--host claude|openai]`
1. **Material built without a model.** The tool reads `scope.md`, `searches/*.md`, `capsule.md` and, if present, `state/calls.jsonl`. Y is condensed at the SHA by `tools/condense_repo.py` (tree, then whole numbered files, declared exclusions, cap of 400 k characters: a file that no longer fits is listed "not included (cap)", never truncated). X is limited to the whole files that the searches read or cited `file:line@SHA` on the X side, plus the seams of the capsule; order: seams, then decreasing citations; cap of 200 k characters. No clone, no execution of the code of Y.
2. **One call, one reader, no tool, fresh context**, same model as the orchestrator by default, under the question: "how are state and evidence represented and linked in Y, and what could X do that it cannot do if it assembled these mechanisms?". Expected output: composite capabilities, then concrete defects of X revealed by the comparison, every claim with its `file:line@SHA` on both sides. Written to `searches/whole-reading.md` with a material header (files included, not included, caps); receipt in `state/whole-reading/receipt.json`.
3. **Treated as one more search**: its capabilities and defects enter the plan revision, the map of Y, the composite synthesis and the verdicts, with the same status as the other searches; every reference is checked by the verifier (section 7) like the others; nothing is claimed on the reader's word alone without a reference.
Measured cost: +0.9 to 2.6 USD per case (65-290 k input tokens), counted apart in the receipt. Measured on our benches on 6 cases: at equal correctness (104/104 against 106/106 existing references) and equal recall on the controls, the reader yields exclusive verified findings in 5 of 6 cases (17 against 14 in total), judges from three model families prefer it 16 of 18 times and the owner 5 of 5 blind. Known limit: above the cap, the cut follows tree order (two large Y repositories were truncated); selection by repository map still to be measured.

## Contradictor after the report (optional, never by default)

When SKILL.md "Contradictor" is switched on (`check_keys.py` prints the families), the engine runs **once**, after `REPORT.md` and before the machine annex:
`python3 -I tools/contradictor.py <run dir> [--families openai openrouter:<vendor/model> ...] [--host claude|openai] [--model M]`
1. **Input built without a model.** The report, the condensed Y of the whole reading cut at 220 k characters at a file boundary (the cut is declared) and the X material of the whole reading, under `tools/prompts/CONTRADICTOR.md`: at most 3 statements of the report judged false (exact quotation + evidence `file:line@SHA` in Y or X + why) and at most 3 composite capabilities or concrete defects of X the report missed (references on both sides), strict JSON, "without a verifiable reference, write nothing".
2. **One call per family, no tool.** A family = a model of another family than the author of the report, written `<via>[:<model>]` (`VP_CONTRADICTORS` or `~/.config/vp/contradictors`): `openai[:<model>]` through the `openai` host profile (Codex CLI, read-only sandbox, empty directory, 0 USD on a subscription; the natural choice on a Claude Code host), `claude[:<model>]` through the `claude` host profile (`claude -p` without tool; the choice on a Codex host), `<provider>:<model>` through any OpenAI-compatible chat-completions API named in `tools/config.json` `contradictor.providers` (`openrouter`, `gemini`, `openai-api`, `mistral`, `ollama`, or one the user adds there or in `VP_CONTRADICTOR_PROVIDERS`), each provider with its own key variable resolved like every key of KEYS.md. No model name is fixed in the code or the config: without `:<model>` a CLI uses its own default, an API needs the model id. Request fields of the measure (temperature 0, 8,000 output tokens) in `contradictor.request`. A missing key, url or command skips the family with the reason (`credential_missing`, `provider_unknown`, `command_missing`), never silently.
3. **Nothing on the contradictor's word.** Mechanical check (the quotation is in the report, every reference names a file and a line of the material, a miss has both sides); one fresh-context call on the host model drops the misses the report already states (same mechanism for the same purpose, whatever the verdict); one fresh-context reread per surviving element with the cited extracts only: CONTRADICTED / NOT CONTRADICTED for a false claim, FOUND / ABSENT for a miss (X-side extracts). Ceiling `contradictor.max_usd` of `tools/config.json` on the rereads.
4. **Applied by the orchestrator, never by the tool.** `contradictor.json` lists every element with its final status. "false detected": the finding that carries the quotation is annotated "contradicted by <family>: <why>", and the quotation leaves the executive summary and the verdicts. "miss verified": a finding "contradictor (<family>)" is added with its references on both sides, verified by the verifier like any other. The methodology appendix states the families, the four counts (false detected, false added, misses verified, misses false or not exclusive) and the cost.
Measured on our benches on 6 cases (the reports of the whole-reading duel) with three families, frozen protocol and criterion (at least 3 cases of 6 with a true detection, and added errors <= true detections): Gemini 6/6 cases, 14 true against 11 added; Kimi 6/6, 20 against 6; Codex 6/6, 20 against 8; 9 of the 29 false statements claimed were confirmed by the reread. Known limits: n = 1 per cell; one reread model (Sonnet) for every family; 36 of 37 misses confirmed by that reread (a lenient judge is possible: the false statements detected are the firmer signal); Gemini adds almost as many errors as it detects, prefer Codex or Kimi (models of 2026-10-27: `gpt-5.6-sol`, `moonshotai/kimi-k3.1-pro`, `google/gemini-4-argon`; other models and providers are not measured); `claude` as contradictor is not measured; exclusivity judged by two other families on our benches, by the host model here.

## Context capsule

This is the input that made the difference in real use (measured on our benches: pinned repository + named seams + registry -> the strong studies; URL alone -> WATCH then nothing). Built by `tools/code_capsule.py` from X, **reviewed by the owner before the study**.
- Exact command: `python3 -I tools/code_capsule.py --repo <X> --sha <40 hex> [--registry <contributions.jsonl>] [--out <DIR>] [--max-bytes 65536] [--max-modules 200]` -> `<DIR>/capsule-<X>@<sha12>.md` + `.json`; everything is read at that SHA (`git show`), nothing of X is executed nor imported.
- The tool fills identity (X@SHA, `tree_sha256`, commit date), licence, module map, entry points (`file:line@sha12`), tests and registry taken as is (path in X read at the SHA, or out-of-tree file pinned by its sha256); it leaves `target_seam`, `intention`, `refusals` (and `reviewed_by_owner: no`) at `TO BE FILLED BY THE OWNER`.
- **The intention and the refusals are written by the owner**, never by the tool nor by the engine; a capsule where they are still to be filled stays `capsule not reviewed`.

Template (`capsule.md` or `capsule.json`, one per request, in the working directory, filed with the report):
```
capsule:
  reviewed_by_owner: yes | no       # with the review date ; "no" or absent -> report labelled "capsule not reviewed"
  X: <repo>@<SHA 40 hex>           # HEAD frozen before the study
  request_date: <ISO>              # = T ; nothing later enters
  target_seam:                     # 1 to 3 seams, each file:line@SHA on the X side
    - <path>:<line>@<SHA> - <what happens there today, in one sentence>
  registry:                        # contributions already known on these seams
    - <contribution id> - <status adopted/removed/pending> - <file:line@SHA or "gone">
  intention: <what the owner wants to obtain, measurable: throughput, invariant, guarantee, cost>
  refusals:                        # what X does not want (core, gate, licences, dependencies)
    - <recorded refusal, with its reason and date>
  mode: Y given | need only
  Y: <repo>@<SHA> (if given), licence read: <SPDX or "to read">
```
How the owner reviews it: (1) X@SHA is the intended freeze; (2) the seams are those that exist and that the owner accepts to touch (adapters and producers, never the core nor the gate); (3) the registry lists the live and removed contributions on these seams; (4) the intention is measurable; (5) the refusals are complete (a missing refusal is an implicit authorisation). A capsule that was not reviewed produces a report labelled `capsule not reviewed`. Without a capsule, or without `X@SHA` in it, the run stops before any collection: report labelled `capsule missing`, empty `result.json`, no invented value.

## Modes

Two modes. The first is the majority use (measured on our benches: 39 studies of 69, 57 %); the second is an **untested hypothesis** (measured on our benches: a repository really borrowed in the top 10, found 0/20), to be measured on real requests.

**Y given.** Input: capsule + Y@SHA. Steps: licence of Y -> inventory of the mechanisms of Y (capabilities, not names) -> presence in X seam by seam (`present / partial / not found`) -> card per absent or partial mechanism -> verification. Refuse what already exists. The engine's searchers (SKILL.md section 4) share the subsystems of Y and the seams of X (one searcher per subsystem or seam); the saturation count (section 5) counts per wave the **new candidate mechanisms**, not the new repositories.

**Need only (discovery).** Input: capsule without Y. Steps:
1. Rephrase the need **by goal**, outside the vocabulary of X and outside the domain (Idea-Catalyst; Hope et al. 2017: search by goal, compare by mechanism; goal / mechanism / evaluation facets of Scideator).
2. Search **wide, across domains, with varied seeds**: several independent queries per goal, on GitHub, Sourcegraph, HF Papers (paper -> code), neighbours by dependencies (deps.dev, ecosyste.ms). Mandatory control noted in the receipt: a random draw of seeds, because targeted cross-domain search does not beat a draw of varied seeds (PaperGym).
3. Prefilter the candidates by code similarity (embeddings) before any LLM judgement **when the gateway supplies that tool**; otherwise note `prefilter: not done (tool absent)` in the receipt, without simulating it; then **compare by mechanism** with snippets at a frozen SHA.
4. Retain only mature tools from a neighbouring domain aimed at an existing seam (what paid off in real use); produce the same cards per mechanism as the Y-given mode.

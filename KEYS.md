# API keys of the VanishingPoint skill (2026-10-26)

Every key is **optional**: without a key, the source concerned is skipped or degraded **with a receipt**, never "nothing found" (SKILL.md "What we do not do"). No key value is ever displayed, journaled or written into a URL. To know what you are missing: `python3 -I tools/check_keys.py` (offline; prints, per plugin, the active, degraded and skipped sources with the link to obtain each key); `--announce` returns this text only on the first run and when the set changes (fingerprint of the names in `~/.config/vp/keys-state.json`); `--suggest "<angles>"` proposes (at most 2) a missing free source when the `useful_when:` line of its plugin overlaps the question.

## Installing a key (one command)

Run **`python3 -I tools/setup_keys.py <NAME>`** (from the skill directory; `NAME` = the variable in any case or a short name: `openalex`, `ncbi`, `github`, `swh`, `piste`, `openrouter`, `gemini`, `mistral`, `openai`, `s2`, `openaire`, `fred`). Without a name it lists every key (present or absent, what it unlocks) and asks which one to install. It shows where to get the key, asks for the value without echo (PISTE: Client ID, then Client Secret), writes `~/.config/vp/<name in lowercase>.key` (directory 0700, file 0600, atomic) and then checks it **live** with one minimal request per source through the gateway's own code paths, one plain line per source: `Judilibre: OK`, `OpenAlex: key refused — check you copied it whole`, `Légifrance: identifiers accepted but the application is not subscribed to this API (...)`. `--check` re-runs only the live check, `--remove` deletes the file(s) after confirmation; from a script the values come from stdin, one per line. Exit code 0 ok, 1 check failed or key not installed, 2 usage. No value is ever printed or logged.

Manual method (secondary): put the value in the file `~/.config/vp/<name in lowercase>.key` (or the environment variable `NAME`), as below.

## How the skill reads a key (single rule, `tools/code_sources.py` `key(NAME)`, reused by the gateway and by the GitHub token)

1. Environment variable `NAME` (exact name declared by the plugin); non-empty value -> taken (surrounding whitespace removed).
2. Otherwise the file **`~/.config/vp/<name in lowercase>.key`**, exact name, "_key" included: `OPENALEX_KEY` -> `openalex_key.key`, `NCBI_API_KEY` -> `ncbi_api_key.key`, `VP_GITHUB_TOKEN` -> `vp_github_token.key`, `PISTE_CLIENT_ID` -> `piste_client_id.key`.

An empty or unreadable file = absent; `None` = the source does without. Nothing is required, no value is displayed or journaled. There is no other lookup location: on a machine where keys were kept elsewhere, copy them to `~/.config/vp/`.

The GitHub token (`read_token()`) follows this same rule; it is sent only as `Authorization: Bearer` to `api.github.com`, never on a redirect, and refused (never sent) if it is not printable ASCII of at least 8 characters (`credential_invalid`).

Today only **`OPENALEX_KEY`** (added as `api_key=` to OpenAlex calls), **`NCBI_API_KEY`** (added as `api_key=` to PubMed E-utilities calls, interval 0.11 s instead of 0.45 s), **`VP_GITHUB_TOKEN`** (GitHub code search) **`SWH_TOKEN`** (Software Heritage, `Authorization: Bearer` to `archive.softwareheritage.org` only, never on a redirect, interval 3 s instead of 6 s) **`FRED_API_KEY`** (v0.4.9, engine `fred`: `api_key=` to `api.stlouisfed.org` only, ALFRED vintage of the eve of T; without key 0 request, `skipped` / `credential_missing`) and the pair **`PISTE_CLIENT_ID` + `PISTE_CLIENT_SECRET`** (v0.4.7, engines `judilibre` and `legifrance`, not yet verified on the live service: OAuth client credentials sent in a form body to `oauth.piste.gouv.fr` only, the bearer token to `api.piste.gouv.fr` only, never on a redirect nor in a URL; token cached in `<state>/piste-token.json`, mode 0600, with its expiry) change a network call; only these are ever suggested by `--suggest`. **A key the provider rejects never breaks a source**: NCBI HTTP 400 "API key invalid" or "API key not wellformed", OpenAlex 401/403, Software Heritage 401/403, FRED 400 whose message names `api_key` (no key-less FRED: the engine is then `skipped` / `key_invalid`, 0 request for the rest of the run; `search-dbnomics` stays), PISTE token request 400/401 or API 401 after one fresh token (no key-less retry: the PISTE engines are then `skipped`; API 403 = `not_subscribed`) -> the call is retried once without the key, the key is dropped for the rest of the run (names only in `<state>/keys-invalid.json`), and every gateway answer carries `key_invalid: ["<NAME>"]` (never the value) for the "Source coverage" block; `check_keys.py` stays offline and does not test keys; `setup_keys.py <NAME> --check` does, live. The contradictor provider keys (`OPENROUTER_API_KEY`, `GEMINI_API_KEY`, ... as named in `tools/config.json`) are read by `tools/contradictor.py` only (contradictor option, never by the gateway) and sent only to that provider's url, as a Bearer header. The others are **declared, with no effect until wired**: `S2_API_KEY`, `OPENAIRE_TOKEN`; `check_keys.py` says so on each line concerned.

## Local dependencies

- **Python >= 3.9** (`code_capsule.py` uses `tomllib` on 3.11+, else `tomli` if installed, else a built-in minimal TOML parser; tested on 3.9 and 3.12); Linux/macOS (`fcntl`). **No pip dependency** at runtime (standard library only, README rule); the tests are `unittest` (`tests/test_code_capsule.py` also runs under `pytest`, which is optional).
- **git** (>= 2.x, tested 2.43) for `tools/code_capsule.py` (`git -C ... ls-tree / show / grep` at a SHA, read-only).
- **Claude Code CLI** (`claude -p`) or **Codex CLI** (`codex exec`) for `tools/verifier.py` and for the whole reading (`tools/whole_reading.py`): paid model calls, billed according to the host's current rules; not needed to search.

## What the report says about keys

- `gateway.py ... sources` returns `keys_present`: the **names** of the variables found by `key()` (plus `GITHUB` if `read_token()` finds a token), never the values, and `key_invalid`: the names of the keys a provider rejected during the run (also on every call answer and in `state/journal.jsonl`).
- `search-code` returns `github: {"status":"skipped","reason":"credential_missing"}` without token; the receipts in `state/requests.jsonl` carry host, status and SHA-256 of the bytes, never the URL nor the token. Engines that are not wired are listed under `not_wired` and refused cleanly.
- `state/journal.jsonl` -> `run.json` (`validate_card.py --header`) counts calls, errors and identifiers seen per command; it contains no key.
- `REPORT.md` carries the **"Source coverage"** block in its Methodology Appendix (active / degraded / skipped, with reason and link to obtain the key), checked by `validate_card.py`; the plugins additionally require a receipt of the sources (`credential: absent`, `not_configured`, `rate_limited`, quotas reached) at the end of the report. The first message of a run announces the sources skipped for lack of a key on the first run or when the set changes (SKILL.md section 0, `--announce`); the final message and the Source coverage block carry, where relevant, the suggestion of a free source that would have served this question (SKILL.md section 2, `--suggest`, `useful_when:` lines of the plugins).

## Identification contact (`VP_CONTACT`)

Level 2 sources and some APIs (SEC) ask for a contact in the User-Agent header. Set `VP_CONTACT` (environment variable, or the file `~/.config/vp/vp_contact.key`, same rule as the keys) to an address you are willing to share with the providers; a team or project address is best. The simplest way: `python3 -I tools/setup_keys.py contact` (hidden input, form checked: one `@` and a domain, file written 0600, then one Unpaywall request as a live check); `check_keys.py` lists `VP_CONTACT` with the keys of the biology, cs-ai, finance and law plugins and `--announce` reports its absence once. A value without `@` is shown as `invalid`. Without it, the skill identifies itself as "VanishingPoint/1 (research skill)" and skips the sources that require a contact, with a receipt.

Since v0.5.7 two wired engines need an **e-mail address** in `VP_CONTACT` (a value without `@` counts as absent for them): `unpaywall` (the API refuses calls without `email=`) and `edgar` (the SEC answers 403 to tools whose User-Agent declares no company contact). Without it they return `{"status": "skipped", "reason": "not_configured"}` with 0 request; the other engines are unaffected. `VP_CONTACT` is not a key: it is sent as the User-Agent contact to every host and as `email=` to `api.unpaywall.org` only. DataCite also grants a higher rate (1,000 instead of 500 requests / 5 min) when the User-Agent carries an e-mail.

## Follow-up, resume and the command-line tools (v0.6.0)

No new key. A follow-up (`tools/followup.py`) uses the same gateway, keys and `VP_CONTACT` as any run, with the parent's gateway cache
linked: an answer already fetched is not requested again. `tools/resume.py` reads the run's files only (no network, no key) and the
resumed run keeps the same gateway counter. The command-line tools not used by the skill by default (`summary.py`, `progress.py`,
`parse_date.py`, `new_run.py`, `cost.py`, `report_lang.py`) need no key and no network.

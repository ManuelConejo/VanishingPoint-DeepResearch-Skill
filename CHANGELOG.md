# Changelog

Entries before v0.6.28 are in the git history of this file (complete up to v0.6.30) and in the GitHub releases.

## v0.6.28 - 2026-11-17 - optional Rebound sub-skill (Frontier)

- Frontier: an explicit VP path (command line, then `FRONTIER_VP_DIR`, even when defined empty) that is missing or invalid now makes setup and VP-dependent commands refuse with exit 2 instead of falling back to a configured or neighbouring VP. The test package installs a safety net (`frontier/tests/sandbox.py`) that blocks Python-level sockets and unregistered program launches; it is not a sandbox. Known limit: native calls are outside its guarantees, and in a filtered run a denial swallowed in `tearDownClass` or `tearDownModule` is not checked. Run the suite in a container without network for real isolation.
- Rebound: each neighbouring idea is criticised alone in a separate context (two objections, one proposed change) after the prior-art searches and before any ranking, then the author may rewrite its statement (`frontier/tools/rebound.py pack | record --critique | repair --repair`). A missing critique is marked `[REB-CRITIQUE]` without blocking; an invalid repair blocks with `[REB-REPAIR]`. The number of critiques is capped by `rebound_critiques_max` in `frontier/config.json`, a rewritten statement by floor(length x 1.25 + 60) characters, and a same-family critic is disclosed. Judged by models only (ideas kept more often after critique and rewrite, novelty unchanged): an aid, not a measured claim.
- Rebound: optional handoff to `frontier/SKILL.md` on explicit request only, with a bilingual opening disclaimer from `frontier/tools/disclaimer.py` on the first physical line; model-judged proposals and test plans are not a measured claim. Cards may include executed test results. Checks reject a leading blank line, spaces or a BOM; same-family tournament comparisons are disclosed in the report.
- Rebound scope: tried on empirical ideas only (finance, medicine, distributed systems, education); `SKILL.md` says not to use it on legal questions.

## v0.6.29 - 2026-11-18 - English public names, bibliography addresses

- Public English names: `tools/read_possibles.py` → `tools/read_candidates.py`, `frontier/tools/tournoi.py` → `frontier/tools/tournament.py`, `frontier/schemas/tournoi.json` → `tournament.json`, `tools/sources/justice_administrative.py` → `administrative_justice.py` (`search_justice_administrative` → `search_administrative_justice`), and `tests/test_check_verif_fixes.py` → `test_check_verification_fixes.py`. Temporary transition scripts remain at `tools/read_possibles.py` and `frontier/tools/tournoi.py`: each prints one `deprecated path, use …` line on stderr and executes the current script with the same arguments and exit status. Remove these transitions in a later release; update installed briefs and commands. Schema and source-module paths are breaking changes. The corresponding test modules use `read_candidates` and `tournament`.
- Input aliases, with a one-line `deprecated name, use …` warning on stderr: gateway command `search-justice-administrative` → `search-administrative-justice`; plugin `engines`/`access` engine `justice-administrative` → `administrative-justice`; configuration `possibles` → `candidate_reading` and `tournoi` → `tournament` (current key wins, with an explicit ignored-key warning when both exist). Output commands, journal pool/engine (`candidate_reading`/`read_candidates`) and messages use English names.
- Local catalogue columns: `note/annee/titre/methode/capacite/entree_sortie/resultat/verif/ampleur` → `relevance/year/title/method/capability/input_output/result/verification/scale`; grid columns and answer keys `donnees/transposable/autre_usage/forme/verifiable` → `data_availability/transferability/other_uses/form_score/verifiability`; effort `faible/moyen/fort` → `low/medium/high`; helper `forme_from` → `form_score_from`. Direction index fields `annee/liste/sujet` → `year/list/subject`. Complete and partial external tables, reordered or extended columns, old answer keys and effort values remain readable, with deprecation warnings. Mixed old/current headers are refused clearly. Only ingest/check require a complete 12- or 19-column header; successful ingest converts the complete table to English, preserving free text, comment positions and blank lines. Reading pads short rows and truncates extra cells; successful ingest writes that normalized content, so extra cells are lost on rewrite. Check reports inconsistent widths. Update reads identifiers without rewriting the table.
- Existing runs: read `tournoi_rebound.json` as `tournament_rebound.json`, and old `material.json` fields; all new writes use English names. `read_candidates.py --state STATE --show` reads saved `possibles.md/json` as `candidate_reading.md/json`, without fetching. If either `candidate_reading.md` or `candidate_reading.json` exists, the current pair is selected and both files are required; an incomplete current pair is refused even when the legacy pair is complete. Only when neither current file exists is `possibles.md/json` selected, again requiring both files. Generations are never mixed and legacy files are retained. For the tournament journal, an existing `tournament_rebound.json` takes precedence; `tournoi_rebound.json` is used only when the current path is absent. Tournament display mark `[TOURNOI]` becomes `[TOURNAMENT]`; cards with the old generated mark require regeneration. Repeats recognize legacy journal commands while preserving filters and pool limits. Batch receipts still do not classify candidates as read: the `read` filter remains the published behavior.

- Rebound cards without a requested debates tournament end with one line: "Ranking of the neighbouring ideas by debates is available on request (tournament)." It counts within the card limit and is omitted after tournament opt-in.
- Bibliography: at closure (`tools/finish_run.py`), a bibliography entry of `REPORT.md` receives the canonical public URL of its identifier (`tools/bibliography_links.py`, rules in `tools/config.json` `bibliography_links`: doi, pmid, arxiv, openreview, hal, nct and others). Only the shape the skill writes is handled: an unindented line `[n] ...` of the level-2 Bibliography section, on one physical line, carrying exactly one configured identifier that fully matches its rule. Anything else is left unchanged. `validate_card.py` warns `address not deducible`, without failing, when the entry carries a configured identifier whose address cannot be deduced: an entry continued on a next line, two identifiers on one line, a malformed or ambiguously punctuated identifier. An identifier in inline code or of an unknown family is ignored without a warning. The scanner is a line scanner, not a Markdown parser: it skips ordinary fenced code and HTML comments, but unusual Markdown (setext headings, raw `<pre>`/`<script>`, nested or indented fences, comment markers inside inline code) can shift what it takes for the section. URLs are deduced from syntax, not checked online; an equivalent URL already written with another spelling may get a second canonical URL once. One DOI period before a space or line end is detached (accepted risk: a DOI truly ending in a period loses it in the URL). HTML and data exports use the same decision. Older reports stay valid.

## v0.6.30 - 2026-11-18 - minimal repository

- The test suites (`tests/`, `frontier/tests/`) and their fixtures are no longer shipped: the repository keeps only what the skill needs to run, the documentation and one example. The suites are still run on the development tree before each release. No tool, prompt or behaviour changes.

## v0.6.31 - 2026-11-18 - strict minimum

- Removed the temporary transition scripts `tools/read_possibles.py` and `frontier/tools/tournoi.py` added in v0.6.29: use `tools/read_candidates.py` and `frontier/tools/tournament.py`. The input aliases (old command, engine, configuration keys, column names, saved state files) are unchanged.
- Removed the example run `examples/report-cs-ai/`; the capsule template and the local-documents source example stay.
- This changelog keeps v0.6.28 and later; a configuration note no longer names an internal run.
